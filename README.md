# IEEE 33-Bus System - 커패시터 최적 배치 프로젝트 (Phase 1: Baseline HW 완결판)

이 레포지토리는 전력공학 IC-PBL 프로젝트의 **공식 기준(Baseline HW)** 환경을 담고 있습니다. 
팀원들은 본 레포지토리의 환경을 그대로 다운로드하여, **추가적인 환경 세팅이나 수정 없이 바로 커패시터 최적화(Phase 2) 개발에 착수**할 수 있습니다.

---

## 🚀 프로젝트 개요
*   **목표**: 22.9kV IEEE 33-Bus 방사형 배전계통(Radial Distribution System)을 모델링하고, 전력조류(Load Flow) 해석을 통해 저전압 모선을 식별한 뒤, 분로 커패시터(Shunt Capacitor)의 최적 위치와 용량을 선정하여 전압 제약을 만족하면서 설치 비용을 최소화합니다.
*   **현재 상태**: 커패시터 미설치 상태(0 VAR)의 **초기 기준 전압 프로파일(Baseline) 검증을 100% 완벽히 완료**한 상태입니다.

---

## 💻 필수 개발 환경 (Prerequisites)
이 프로젝트는 팀원 간 호환성 문제 및 Simulink 오류를 방지하기 위해 다음 환경을 공식 기준으로 사용합니다.

*   **SW 버전**: MATLAB **R2024a**
*   **필수 툴박스**:
    *   Simscape
    *   Simscape Electrical
    *   Simulink
    *   Optimization Toolbox

> **⚠️ 주의**: 하위 버전(예: R2023b 이하)에서 실행할 경우 Simscape 블록 호환성 문제나 `sim` 명령어 에러가 발생할 수 있습니다. 가급적 **R2024a** 사용을 권장합니다.

## 📂 핵심 파일 설명

*   **`Power_System_33Bus_Modeling_test.slx`**: 
    *   물리적 결선, 파라미터, 토폴로지가 100% 공식 IEEE 33-Bus 스펙에 맞게 검증된 완벽한 시뮬링크 모델입니다. **이 파일은 수정할 필요가 없습니다.**
*   **`setup_env.m`**: 
    *   프로젝트 전역 상수(기준전압 22.9kV, 주파수 60Hz, 1MVA), 공식 분기선/부하 파라미터 배열, 최적화 비용 함수 등이 정의된 환경 설정 파일입니다.
*   **`run_baseline.m`**: 
    *   커패시터 미설치 상태로 시뮬레이션을 돌리고, 정상상태 p.u. 전압을 추출하여 그래프로 그려주는 핵심 스크립트입니다.
*   **`set_voltage_22900.m`**: 
    *   (참고용) 모든 SLX 블록의 전압을 22900V 선간전압으로 일괄 통일할 때 사용한 스크립트입니다.

## 🏃 퀵 스타트 가이드 (사용 방법)

1.  이 폴더(레포지토리)를 MATLAB의 '현재 폴더(Current Folder)'로 설정합니다.
2.  MATLAB 명령창(Command Window)에 아래 명령어를 입력하여 실행합니다.
    ```matlab
    run('run_baseline.m')
    ```
3.  **약 30초 ~ 1분** 정도 기다리면 시뮬레이션이 완료됩니다.
4.  콘솔 창에 각 Bus 별 전압 표가 출력되고, **[베이스라인] 전압 프로파일 그래프** 창이 뜹니다.
5.  `baseline_result.mat` 파일이 작업 공간에 저장되어, 향후 분석 시 데이터를 바로 로드하여 사용할 수 있습니다.

> 💡 **RCOND 경고 메시지 안내**
> 시뮬레이션 중 명령창에 출력되는 `행렬이 특이 행렬에 가깝거나... RCOND = 1.44e-17` 등의 노란색 경고문은 에러가 아닙니다. 22.9kV의 매우 큰 전압/전력 단위와 0.0001 단위의 미세한 선로 저항이 섞여 행렬을 풀 때 발생하는 수치해석 상의 경고이며, **결과에 영향을 주지 않으니 무시하셔도 됩니다.**

## 🚨 팀원 필독 사항 (데이터 맵핑 주의점)

팀원들이 향후 데이터를 직접 뽑아서 사용할 때 **반드시 알아야 할 매우 중요한 사실**입니다.

SLX 모델의 전압 출력 블록(`simOutputV`)에서 나오는 데이터 배열은 `Bus 1, Bus 2, Bus 3 ...` 순서가 **아닙니다**. 
출력 배열은 물리적인 **`Branch(선로)` 번호 순서(1번 선로의 끝단 전압, 2번 선로의 끝단 전압...)**로 정렬되어 있습니다.

*   예: `simOutputV`의 17번째 데이터는 Bus 17이 아니라, 17번 선로의 끝단인 **Bus 18**의 전압입니다. 
*   이를 무시하고 배열을 그대로 Plot하면, 하위 모선의 전압이 갑자기 높아지는 듯한 완전히 잘못된 그래프가 나옵니다.

이를 해결하기 위해 `run_baseline.m` 내부에는 **배열 인덱스를 실제 Bus 번호로 다시 끼워 맞추는(Mapping) 로직**이 이미 구현되어 있습니다. 
따라서 앞으로 전압 데이터를 분석하실 때는, **반드시 `run_baseline.m`에서 생성해 주는 `V_bus_pu` (1x33 크기 배열, 인덱스 번호 = Bus 번호) 변수를 사용**하시기 바랍니다.

## 🎯 다음 단계 (Phase 2)

베이스라인 결과, 가장 먼 끝단인 **Bus 18 (0.880 p.u.)**을 비롯하여 **총 12개 모선**이 허용 하한치(0.90 p.u.)를 밑도는 저전압 위반 상태임을 확인했습니다.

이제 팀원들은 이 기준 폴더를 바탕으로, 다음의 최적화 알고리즘 설계를 진행하면 됩니다:
1.  **민감도 분석**: 특정 Bus에 커패시터를 설치했을 때 전압이 얼마나 개선되는지 확인
2.  **최적화**: 비용 함수 `C(D)`를 사용하여 전체 전압을 0.90 p.u. 이상으로 끌어올리면서도 총 설치 비용이 최소가 되는 위치(어느 Bus?)와 용량(얼마의 VAR?) 도출
